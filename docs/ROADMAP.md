# TrustAgent 版本路线图

## 1. 第一版（阶段1–3）边界

### 已纳入第一版

| 能力 | 第一版实现方式 | 刻意选择的“够用”方案 |
| --- | --- | --- |
| 认证 | 无状态 JWT（HMAC-SHA256） | 不做 OAuth2/OIDC、不做刷新令牌轮换 |
| 授权 | RBAC（用户-角色-权限点），方法级 `@PreAuthorize` | 不做 ABAC、不做数据行级权限 |
| Agent 执行 | Python 单进程 FastAPI，同步 HTTP | 不做多副本负载均衡 |
| LLM | 默认 `MockLLMProvider`（确定性），选配 OpenAI 兼容 | 不加载本地权重 |
| 注入检测 | 可解释正则 + 规范化流水线，`Detector` 接口 | 不训练分类模型 |
| PII 检测 | 正则 + 校验位规则 | 不默认引入 Presidio/NLP 模型 |
| 异步评测 | Redis Streams + Consumer Group + 死信 | 不做 Kafka |
| 任务结果 | MySQL 单库事务 + 唯一键幂等 | 不做分布式事务 |
| 审计 | 哈希链（tamper-evident） | 不做外部存证/签名（见限制文档） |
| 可观测 | 结构化日志 + Trace ID 贯穿 | 不做 OpenTelemetry |
| 部署 | docker-compose 单机 | 不做 K8s |

### 第一版验收标准（阶段1）

1. 新环境按 README 可以启动（`docker compose up` 或 `dev` profile 零依赖启动）。
2. Mock 模式下**不需要任何外部 API Key**。
3. 正常工具调用成功（场景A）。
4. 越权工具调用在**执行前**被阻止（场景B）。
5. 敏感信息被脱敏并产生安全事件（场景D）。
6. 全部单元测试通过，且汇报真实通过/失败数量。

### 第一版验收标准（阶段2）

1. `datasets/` 中合成评测集 ≥100 条，覆盖 8 个类别，导入校验能拒绝坏行并给出原因。
2. 评测任务异步执行，可查进度，单条失败不影响整体，失败可重试。
3. 能导出 `BOTH` 模式下的防护开/关对比指标（JSON + CSV）。
4. 审计链验证能定位被篡改的首个 `seq`。
5. 对应测试全部通过。

### 第一版验收标准（阶段3）

1. 前端 9 个页面均调用真实接口，首页数字来自真实统计接口。
2. `docker-compose.yml` 一键启动；CI 配置可在 GitHub Actions 运行。
3. k6 两套脚本存在但**默认不执行**。
4. 10 份文档 + 简历草稿齐备，Mermaid 图可渲染。

## 2. 阶段4（可选增强，第一版稳定后再做）

按优先级排序，每项都写清楚“为什么现在不做”：

| 项 | 引入条件 | 价值 | 现在不做的原因 |
| --- | --- | --- | --- |
| OpenTelemetry + Prometheus + Grafana | 需要跨服务链路与指标时 | 生产级可观测 | 引入全套采集与存储，学习成本高、对简历边际收益低于评测与审计 |
| Kafka 替换 Redis Streams | 需要多消费者组独立重放、消息保留策略、跨机房时 | 吞吐与生态 | 单机评测量级（百条用例）用不上；Redis Streams 已能演示消费组与幂等 |
| MinIO | 评测集/报告文件变大（GB 级）时 | 对象存储 | 当前数据集是几百 KB 的 JSONL，进 MySQL 足够 |
| AgentDojo 适配器 | 想跑公开基准时 | 与学术界可比 | 需对齐其环境与工具语义，属独立工程 |
| PyRIT 适配器 | 想接入自动化红队时 | 攻击用例生成 | 与已有评测集职责重叠，先做自研再谈集成 |
| Presidio 适配器 | 需要多语言/统计式 PII 识别 | 更高召回 | 会拉取 NLP 模型，违反“不默认下载大模型”约束；接口已预留 |
| 真实交通预测模型 | 有真实数据与算力 | 业务闭环 | 本项目定位是 Agent 安全网关，交通只是预留的一个工具示例 |
| 测试服务器部署 | 有可用服务器与授权 | 在线演示 | 需求明确禁止擅自部署公网 |

## 3. 演进路径（如果要继续做一学期）

1. **检测器可插拔**：把 `Detector` 接口扩展为“规则集 + 模型集”两级，加置信度与阈值配置。
2. **策略表达式化**：把目前的字段式策略升级为可版本化的策略 DSL（如 CEL），支持条件组合。
3. **审计外部存证**：周期性把链尾哈希写入只追加的外部存储（如对象存储 WORM 桶），形成“本地链 + 外部锚点”。
4. **多租户**：引入 `tenant_id` 并在所有查询里强制注入租户过滤，配套越权测试。
5. **评测集版本管理**：数据集支持 `v1/v2` 与用例级 diff，便于回归比较。
